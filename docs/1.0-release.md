# 1.0 Release Checklist

This checklist defines the release surface for the Dynamic Modules repo family.

## Release scope

- Dynamic SS13 Modules framework: discovery, resolution, prepare output,
  lockfiles, config export, structured patches, local module patches,
  prepare-plugin API, update commands, and generated editor metadata.
- Dynamic DM: DM metadata index plus verified DM patch conversion.
- Dynamic TGUI: host tgui wrapper, runtime overlays, AST/text patching,
  whole-file overrides, final-source generation, and migration tooling.
- Dynamic Assets: asset contribution indexing for modules and maintainer tools.
- VS Code extension: index browsing, file interaction hovers, branch conversion,
  authoring workspaces, and deconversion back into modules.
- Module List: trusted default registry metadata for the core modules and
  example modules.

## Validation Matrix

Run these before tagging or announcing a 1.0 release:

```bash
# Dynamic-SS13-Modules
python3 -m unittest discover -s tests
python3 -m dynamic_ss13_modules --version

# Dynamic-DM
python3 -m unittest discover -s tests
python3 -m py_compile prepare_plugin.py dynamic_dm/*.py

# Dynamic-TGUI
bun install
bun test

# Dynamic-Assets
python3 -m py_compile prepare_plugin.py

# VS-Code-Extensions
node --check extensions/dynamic-ss13-modules/extension.js
python3 -m json.tool extensions/dynamic-ss13-modules/package.json

# Module-List and module config schemas
python3 -m json.tool modules.json
python3 -m json.tool schema.json
python3 scripts/validate_registry.py
```

For an end-to-end host smoke test, install the core modules plus an example
module into a tgstation-style checkout, then run:

```bash
python3 tools/dynamic_modules/prepare.py
python3 -m dynamic_ss13_modules --root . doctor
python3 -m dynamic_ss13_modules --root . patch-report
```

## Release order

1. Tag and push Dynamic SS13 Modules.
2. Tag and push Dynamic DM, Dynamic TGUI, and Dynamic Assets.
3. Tag and push example/gameplay modules.
4. Update and push Module List metadata.
5. Publish the VS Code extension package.
6. Update downstream bootstrap branches or PRs to reference the tagged core
   module versions.

## Commit policy

Commit:

- host `dynamic_modules.toml`
- module manifests
- module source/config/test files
- `dynamic_modules.lock.json` when a host repo pins installed modules

Do not commit:

- `.dynamic_modules_build/`
- `.dynamic_modules_authoring/`
- generated final source copied only for inspection
- local editor/workspace scratch output

## Known 1.0 boundaries

- Dynamic Assets 1.0 indexes asset contributions. It does not yet rewrite or
  bundle host asset files.
- Structured patches remain an escape hatch. Prefer normal module DM files,
  signals, components, generated hook points, or Dynamic TGUI AST patches.
- Authoring deconversion is a maintainer tool. Always run `prepare` and inspect
  the final output before committing generated module changes.
